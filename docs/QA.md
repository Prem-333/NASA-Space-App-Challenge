## Browser coverage

- Mission selection; starter loading; all six system categories.
- Insufficient fuel disables launch; restoring the starter recovers readiness.
- Spacecraft naming and save/resume after a reload midflight.
- Share URL copies and reconstructs the same design in another tab.
- JSON export and import; report download.
- Complete flyby, orbiter, and lander missions.
- Lander science-objective failure from the lower-science choice sequence.
- Archive persistence and reading historical results without overwriting an active flight.
- Abort confirmation.
- Malformed storage and malformed design links recover safely.
- Desktop, tablet and phone navigation.
- Active phone flight and completed phone debrief.
- Game operation with outside network traffic blocked.

Audited with axe-core: desktop briefing, builder, active flight, debrief, manual; mobile briefing, active flight, debrief. This is automated testing of representative states, not an exhaustive accessibility certification or a screen-reader usability study.

## Visual inspection

Rendered desktop mission desk, spacecraft lab, flight console and debrief were inspected, along with mobile briefing and builder. Additional phone flight/debrief screenshots were captured. Evidence is in the local `artifacts/` folder and is regenerated by `npm run test:e2e`.

## Scientific coverage

Tests verify the NASA ideal-rocket-equation relationship, burn inversion, sequential mass conservation, dry/wet mass effects, power-versus-energy units, launch and science constraints, communication bottlenecks, deterministic outcomes, saved-state replay, and malformed-input normalization. This verifies the implemented educational model; it is not independent validation of a real spacecraft design.

## Known limitations

- The official full challenge page returned HTTP 502 through the available web tool. Its exact current rubric and resource requirements were not verified. The project follows the available mission-design-game summary.
- Tests were run in Chrome on this Windows host. Mobile viewport testing does not substitute for physical iOS/Android testing.
- No full numerical orbit propagator, launch-window computation, live telemetry, or continuous electrical simulation is present; these limits are explained in the product.
- Browser storage is device-local and may be cleared by the browser. Reports and exported designs provide a portable copy.
- Private hosting requires viewer access. Judges will need a public deployment or deliberately granted access.
- Source, design choices, and copy are provided for the team to review. No competition submission has been sent.

## Reproduce

In one terminal: `npm start`.

In another: `npm ci`, `npm run check`, `npm test`, then `npm run test:e2e`.

The browser test regenerates `artifacts/accessibility.json`, screenshots, and sample exports. It fails on functional errors, page/console errors, unexpected failed requests, or reported accessibility violations.
